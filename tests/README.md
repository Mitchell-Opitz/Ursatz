# Tests

Tests are registered with `ursatz_test()` (`cmake/UrsatzTest.cmake`; `ursatz_test_executable()` and `ursatz_test_library()` build shared helpers). It compiles every test executable with `-UNDEBUG`, so asserts hold in any build type (a test may call a function inside `assert`; the guard `test_asserts_on` fails when `NDEBUG` reaches a test), defines `URSATZ_FIXTURES_DIR` (the root `tests/fixtures`), and sets the timeout (120 s, or 1800 s for a `slow` test). Labels: `slow` (nightly only), `valgrind` (always with `slow`), `schema`, `accuracy`, `golden`. Some tests need valgrind, python3 with jsonschema or node (`cmake/UrsatzTools.cmake`); a test whose tool is missing is not registered, and `-DURSATZ_REQUIRE="valgrind;jsonschema;node"` makes the configure fail when a named tool is missing.

Goldens: the tests labelled `golden` compare their output with checked-in files (`analyzer/tests/snapshots`, `composer/tests/snapshots`, `tests/fixtures/forms`, `gui/backend/tests/fixtures/pieces`). One switch updates all of them: `cmake --build build --target update-goldens` (build the tree first) runs `ctest -L golden` with `URSATZ_UPDATE_GOLDENS=1`, which makes every golden test write its files, then runs `ctest -L golden` again without the switch and fails when that run does. The update run fails on purpose: a test run with `URSATZ_UPDATE_GOLDENS` set exits 2 and prints `<test>: goldens updated (URSATZ_UPDATE_GOLDENS)`, so CI can never pass in update mode. Review the changed files with `git diff` and commit them in their own commit. The chain digests (inline in `test_analysis_chain.c`, printed by `URSATZ_CHAIN_DUMP=1`) and the accuracy baseline (`accuracy_harness --update-baseline`) are not goldens in this sense.

## Fixtures

`tests/fixtures/` holds the reference pieces and annotations every part's tests read, once ([README](fixtures/README.md)). Tests find it through `URSATZ_FIXTURES_DIR`.

## Support

`tests/support/` holds what every part's tests share: `ursatz_test.h` (library `ursatz_test_support`: `CHECK`, `CHECKF`, `test_finish`, file reading and writing, temp paths, JSON helpers, and `test_smf` and `test_smf_type0`, the one builder of a standard MIDI file), `ursatz_test_knowledge.h` (the embedded knowledge snapshot a test passes where code wants one: `test_knowledge()` and `test_materials()`) and `test_http.h` (library `ursatz_test_http`: a plain HTTP client, linked only by the GUI backend tests). Helpers that belong to one part (the Analyzer's `test_analyzer_options`, the Composer's oracles, the GUI's `gui_check.h`) stay in that part's `tests/support` or `tests/` folder. The frontend tests share `gui/frontend/tests/support/` (`check.js`, the fixtures and the fake DOM).

## Checks

Every include follows the layer table, `cmake/layer-table.txt` (test `layer_table`, in the fast set): the module of every C file, what each module may include, and a few rules that are not include edges.

`tools/ci/` holds the boundary, docs and test-timing scripts, each runnable from anywhere in the repository after the build, and each also a test: `check-docs.sh <part>` is `docs_<part>` for `library`, `analyzer`, `composer`, `gui`, `workshop`, `common`, `cli`, `knowledge`, `tools` and `tests`, and `docs_root` (`check-docs.sh .`, the root folder's own `.md` files only); `check-statics.sh` is `statics`, `check-hearing.sh` is `hearing_boundary`, `check-frontend-theory.sh` is `frontend_theory`, and `check-reach.sh` is `reach` (slow: it builds its own tree, and CI runs it as a step with ccache). `slowest-tests.sh build` prints the ten slowest tests, warns on a fast-set test over 10 s and fails CI on one over 30 s. The checks are themselves tested: `check_layer_table_self_test`, `check_primitives_self_test` and `check_exports_self_test` plant a violation in a temporary tree and expect the checker to find it, `update_goldens_script` runs the goldens script against a passing and a failing ctest, and `test_ports_unique` fails when two test sources use one port from 18000 to 18999 (`ctest -j` runs them together). A CLI test that has no python3 with jsonschema prints `schema not checked`, and the configure says which tests those are.

`check-primitives.sh` (test `primitive_owners`, in the fast set) refuses a copy of a shared primitive outside its owner (R-622): a gcd function, `__int128`, a type named `*Rational`, `*Fraction` or `*Ratio`, a table of the twelve pitch names, a scale-step table or a table of Roman numeral names in `common/`, `library/`, `analyzer/`, `composer/` or `gui/backend/src`; the owners are `library/model/core/rational.{c,h}`, `library/model/pitch/`, `library/theory/tonality/` and `knowledge/`, and `tools/ci/primitive-allow.txt` lists what stays with a reason and the phase that removes it. `check-reach.sh` builds its own scan tree (`build-reach` by default, tests off) and lists every function in the repository's own C code that no application main (`ursatz`, `ursatz-gui-backend`) reaches, in `<scan build dir>/reach/unreached.txt`. CI runs it with `tools/ci/reach-allow.txt`: a function no application reaches fails CI unless it is listed there with a reason, and a listed one that is reached or gone fails too. Delete such a function, or list it.
