# time

[Docs index](../README.md): the Ursatz docs by topic.

Layer L2 (`music-time`). Path `model/time/`, tests `tests/time/`. Depends on `identity` and `core` only. Sibling of `pitch`; the two do not depend on each other.

## Provides

`Duration` (magnitude), `MusicalTime` (position) and `TimeSpan` (a half-open interval between two `MusicalTime`s) are plain values: each is a struct you copy, compare and pass by value, and none is ever allocated. `TemporalAnchor` (wraps a `MusicalTime`, situates a higher-layer object at that position) and `MetricalPosition` stay small heap holders with their own create and destroy. All rational quantities are exact, never float or double (Law 19).

Four kinds of time (R-532, R-588), each with its conversions: absolute time (`MusicalTime`, whole notes, the one every analysis and composition holds), notated position (`NotatedPosition`: measure, beat, offset, through a `MeterMap`), the local rhythmic grid (`MeterGrid`: the beat and the division of the measure a time is in), and performance time (seconds, through a `TempoMap`). The conversions are `meter_map_position_of`, `meter_map_grid_at` with `meter_grid_holds`, and `tempo_map_seconds_at` with `tempo_map_time_at`.

`MetronomeMarking` (a beat unit plus beats per minute, both exact rationals), `NoteValue` (a written rhythmic value, breve through 1024th, with up to four dots), `TimeSignature` (a top number, an undotted bottom unit and the beat groups the top falls into), and `Tuplet` (a ratio of notes played to notes replaced), `MeterMap` (the time signatures of a piece laid over its time), `TempoMap` (the tempo of a piece over its time), and `MetricalPosition` (where a time falls in a measure) are also provided.

## Notes

- `Duration` and `MusicalTime` are structurally identical (numerator/denominator, reduced to lowest terms) but are separate, non-convertible types. One is a magnitude, the other a position. There is no conversion between them, and none should be added.
- **Time values.** `MusicalTime` and `Duration` each hold one `Rational` (`.value`, `core/rational.h`): lowest terms, positive denominator, and for a `Duration` a value of 0 or more. `musical_time_make` and `duration_make` build one from a numerator and a denominator (`..._ERR_NON_POSITIVE_DENOMINATOR`, `DURATION_ERR_NEGATIVE`, `..._ERR_OVERFLOW`); `musical_time_of` wraps a `Rational` and `duration_of` checks one. `musical_time_cmp` returns -1, 0 or 1 and cannot overflow (a `Duration` is compared by `rational_cmp` of its values); `musical_time_same` and `duration_same` test equality; `musical_time_plus` and `duration_plus` add and report overflow. Every builder and sum writes its output only on success. A struct literal holding the same `Rational` equals the made value, byte for byte.
- **`TimeSpan` is half-open.** A span is `{MusicalTime start; MusicalTime end;}` and always means `[start, end)`: it holds its start and not its end (R-585). The boundary member and its four-way vocabulary are gone, so no payload can omit or misstate one. `time_span_make` refuses an end before the start (`TIME_SPAN_ERR_END_BEFORE_START`); an empty span is legal. `time_span_holds` is true for a non-empty span.
- **The heap time API is gone.** The three types have no heap constructor, no destroy, no allocation error code, no numerator or denominator accessor, and the `Rational` bridge header is deleted: a caller reads a `Rational` as `.value`. Code holds times, durations and spans by value, in structs and arrays, and a function that takes one takes it by value or by `const` pointer.
- `MusicalTime` has no lower bound enforced at this layer. Negative positions (pickup measures, for example) are legal here. What a negative position means is deferred to a later spec.
- `time/meter_arithmetic.h` is the exact measure and beat arithmetic over a `MeterMap`, on `Rational` (whole notes, no floating point). `meter_map_measure_of`, `meter_map_last_measure_touched` and `meter_map_measure_bounds` locate a time (a barline belongs to the measure that starts there). `meter_map_beat_length` is the time signature's own beat length (`time_signature_beat_length`, below), not a rule of its own. `meter_map_position_of` gives the notated position of a time (it replaced `meter_map_beat_of`, which counted bottom units and had no caller outside tests); `meter_map_snap_to_beat` gives the first beat at or after a time, never past the measure end; `meter_map_on_beat` and `meter_map_first_counted_measure` complete the set. Every function returns a `MeterMapResult`, writes its outputs only on success, and reports `METER_MAP_ERR_OVERFLOW` (new, additive) where an exact value does not fit; a negative time is `METER_MAP_ERR_TIME_BEFORE_START`. A framework that needs a measure or beat computation wraps these and does not write its own.
- `time/score_time.h` is the one kernel owner of the measure, beat and snap reads an analysis adapter needs (R-288): `score_time_measure_bounds`, `score_time_beat_length` (both over `meter_arithmetic.h`) and `score_time_snap` (the nearest multiple of 1/grid within 1/tolerance, a half rounding up). Each returns `bool`, false when an argument is invalid or a value does not fit a `Rational`, and writes its outputs only on true. There is no unchecked fallback. The standard-meter, standard-form and standard-texture time modules wrap these and keep their signatures until they are retired; their plain-value operators return 0/1 on overflow. `MeterMap` itself computes on `Rational` and reports `METER_MAP_ERR_OVERFLOW` from creation and lookups where a grid step does not fit.
- `time_span_holds` (`time/time_span.h`): true when the end is strictly after the start, compared exactly. It replaces the per-framework span checks.
- `TemporalAnchor` carries no fields beyond the wrapped `MusicalTime`. It exists so callers building on `Occurrence` (L1) gain a temporal position without embedding position semantics into `Occurrence` itself. It stays a small heap holder because it bears identity for events and positions, as does `MetricalPosition`; a later phase revisits both with note ids.
- `MetronomeMarking` holds a beat unit and a rate in beats per minute as exact rationals, never float/double (Law 19); it does not derive seconds (one beat unit lasts 60/bpm seconds), since no caller needed them. Textual tempo words are not metronome markings; they live in `events/tempo_marking.h` and `theory/markings/`.
- `NoteValue` is notation vocabulary, not a magnitude: it holds a power-of-two exponent (breve -1, whole 0, half 1, quarter 2, ...) and a dot count, and does not convert to a `Duration` (`note_value_duration` was deleted, P55: nothing called it). There is no conversion back either, because many written values share a length. It carries no names, flags, or glyph conventions.
- `TimeSignature` is the two numbers of a time signature, a top number (1 to 64) and an undotted bottom unit from the whole note to the sixteenth, and the beat groups the top falls into. In a simple meter the top counts beats over a beat unit; in a compound meter it counts divisions (6/8 is two beats of three eighths); the groups state which, and naming the category (duple, triple, quadruple) is `theory/meter/`. It is not a fraction: 2/4 and 4/8 have the same measure length (`time_signature_measure_duration`, top times the unit's length, true for simple and compound alike) but are not equal. A dotted bottom unit is rejected.
- **Beat groups, and the one owner of the beat (R-587).** A `TimeSignature` holds its beat groups: the beats of a bar counted in bottom units, whose sum is the top number. `time_signature_create` gives the default groups: a top above 3 that 3 divides is groups of three (6/8 and 6/4 are 3+3, 12/8 is 3+3+3+3), any other top is one unit per group (4/4 is 1+1+1+1, 5/8 is 1+1+1+1+1). `time_signature_create_grouped` takes 1 to 16 groups of 1 to 16 units as given (3+2 over 8 for an additive 5/8), refusing others with `TIME_SIGNATURE_ERR_GROUPS_OUT_OF_RANGE` and a sum above the top number range with `TIME_SIGNATURE_ERR_TOP_NUMBER_OUT_OF_RANGE`. The readers are `time_signature_group_count`, `time_signature_group_at`, `time_signature_is_compound` (two or more groups, all of three: 6/8, 9/8, 12/8, 6/4, 15/8) and `time_signature_beat_length`, which is the one answer to how long a beat is: the group length when every group is the same size (4/4 a quarter, 6/8 a dotted quarter, 6/4 a dotted half), else the bottom unit (3+2 over 8 has eighth-note beats, so every reader of beats reads an additive meter as it reads 5/8). `time_signature_equals` compares groups, and `time_signature_copy` keeps them. Every reader of beats calls the signature: `meter_map_beat_length`, `score_time_beat_length`, the standard-meter classification (`theory/meter/meter_class_rules.c`), the metric grid, MusicXML beaming and the score quantizer, the meter analysis check and the Composer's compound-beat reads (through `plan_meter_signature`). Where the old per-reader rules disagreed (6/4, 9/4, 12/4, 6/2, 15/8) they now follow OMT I ch. 10: a group of three is a compound beat, so 6/4 has a dotted-half beat, 15/8 is compound with five beats and no duple, triple or quadruple name. A MusicXML `<beats>3+2</beats>` imports as groups 3 and 2 and exports back as `3+2`.
- **Notated position (R-588).** `NotatedPosition` is `{measure, beat, offset}`: the measure as `MeterMap` numbers it, the beat counted from 1 by beat group, and the offset from that beat's start in whole notes. `meter_map_position_of(map, t, &p)` is the conversion to a position (its inverse, `meter_map_time_of`, is in the tests' `tests/support/meter_test_access.h`), pickup aware like `meter_map_measure_of`, and exact inverses; `meter_map_time_of` refuses a measure below the first, a beat outside the groups, a negative offset and a position at or past the measure's end (`METER_MAP_ERR_INDEX_OUT_OF_RANGE`). In 3+2 over 8 the second beat starts at three eighths.
- **The local rhythmic grid (R-588).** `meter_map_grid_at(map, t, &grid)` gives the `MeterGrid` of the measure that holds `t`: its signature (borrowed from the map), the measure's start, the beat (`time_signature_beat_length`) and the division, half the beat in a simple meter and a third of it in a compound one. `meter_grid_holds(&grid, length, finest)` is true when `length` is a whole number of one of the grid's levels at least `finest` long: the beat, the division, the division halved down to `finest`, and the tuplets of the beat and of the division (the 3:2 tuplet, two thirds of the level, in a simple meter) or of the beat (the 2:3, half of it, in a compound one). In 4/4 with `finest` 1/32 a length of 1/12 holds (the triplet eighth) and 1/24 does not.
- **Local meter maps.** A MusicXML import keeps each part's own `MeterMap` where parts disagree about the meter: `MusicXmlImport.part_meter_maps` has one entry per part, NULL where the part follows the movement's map, and the movement's `meter_map` stays the lowest part's with the warning kept. A time has one notated position under each map, so `meter_map_position_of` takes whichever map governs the part. A two-part import in 3/4 against 6/8 holds both. No reader uses the part maps until the performer parts (P59).
- `Tuplet` is only a ratio: `actual` notes in the time of `normal` (3:2, 2:3, 5:4). It holds no note value or position, and scales no `Duration` (`tuplet_note_duration` and `tuplet_span` were deleted, P55). The counts are bounded (2-64 and 1-64) and unequal, and the ratio is not reduced, so 6:4 and 3:2 differ. Which meter a tuplet is borrowed from is `theory/meter/`.
- `MeterMap` (`time/meter_map.h`) is the single source for measure boundaries: an ordered, non-overlapping, gap-free list of regions, each `{TimeSignature, start, end or open, first measure number}`. It holds meter only, makes no claim about beats or beat strength, and does not read a signature as simple or compound (that is `theory/meter/`). It depends on `identity` and `time` only.
  - **Regions and measures.** The first region starts at 0 and the last is open. A region's measures are laid from its start in steps of its signature's measure duration. If the next region starts before the last measure is complete, that measure is a short measure: it counts as one measure, ends where the next region begins, and the next region starts a fresh grid there. A change point repeating the previous signature on one of its barlines adds nothing and is dropped; mid-measure it is kept and ends a short measure.
  - **Numbering.** Measure numbering follows the score: the first full measure is 1, numbers run on across regions, and a short measure keeps its number (a 4/4 measure cut short by a 3/4 change is still measure N, and the 3/4 region begins at N+1).
  - **Pickup.** A pickup is measure 0 and is detected only when the file says so, never from note content. The first region is a pickup if a region follows it and either its length is less than one measure of its own signature (a partial first measure ended by a later time signature event), or it is exactly one measure of its own signature, differs from the next signature, and its measure is less than half of the next region's measure (a short leading signature such as 1/8 or 3/8 before 12/8). The half threshold is a convention: it keeps a genuine 3/4 first bar before a 4/4 from reading as a pickup.
  - **Barlines.** A barline time belongs to the following measure: spans are left-closed, `[start, end)`, and `meter_map_measure_index_at(barline)` is the measure that starts there. `meter_map_measure_count(end_time)` counts the measures that start before `end_time` (a pickup included), so an end on a barline adds no empty measure and an end inside a measure counts that measure.
  - **Defaulted.** A region is defaulted when the file declared no signature for it. `meter_map_create_defaulted` makes one 4/4 region marked defaulted; if the first declared signature is after tick 0, the span before it is a defaulted 4/4 region. `meter_map_is_defaulted` is true when every region is, so a consumer can tell a declared meter from a default.
  - **Copy.** `meter_map_copy(map, &copy)` is a deep copy made inside `meter_map.c`: the id's value, every region's id, start, end, signature with its groups (`time_signature_copy`), defaulted flag and pickup. It shares nothing with the original and outlives it; a movement takes a copy of a map it did not make (P59).
  - **Lookups.** `meter_map_region_at`, `meter_map_measure_index_at`, `meter_map_measure_span` (a new left-closed `TimeSpan`; a short measure's span is its real extent), `meter_map_region_of_measure` and `meter_map_measure_count`. Change points must be strictly ascending: two at one time are an error, since there is no way to say which wins.
- `TempoMap` (`time/tempo_map.h`) holds the tempo of a piece over `MusicalTime`: an ordered, gap-free list of regions, each `{start, microseconds per quarter note}`, the first from 0 and the last open. It is the performance-time kind: `tempo_map_seconds_at` gives the exact seconds at a time (a `Rational`) and `tempo_map_time_at` the time at exact seconds, its inverse, so `tempo_map_time_at(tempo_map_seconds_at(t)) == t`; a negative time or seconds is `TEMPO_MAP_ERR_NEGATIVE_START`. The renderers read the region list to place tempo changes; the map renders and exports nothing. It depends on `identity` and `time` only.
  - **Symbolic time is tempo-independent.** A `MusicalTime` or `Duration` means the same with or without a `TempoMap`. The map only says how fast it is played. It is also not a tempo marking: `MetronomeMarking` and `TempoMarking` are notation-level values and are neither replaced nor produced here.
  - **Metric modulation.** A change point is absolute (`microseconds_per_quarter`, as always) or a metric modulation `{old_value, new_value}`: the new tempo makes `new_value` last as long as `old_value` did at the tempo in force. A quarter that becomes a dotted quarter (`{1/4, 3/8}`) at 500,000 leaves 333333 1/3 microseconds per quarter, and `{3/8, 1/4}` after it goes back to 500,000 exactly. `tempo_map_create` resolves a modulation against the previous region's exact tempo, so the seconds stay exact where `tempo_map_region_microseconds_per_quarter` reads the whole microsecond. A modulation at 0 (no tempo before it) or with a length that is not above 0 is `TEMPO_MAP_ERR_BAD_MODULATION`.
  - **Overflow.** A map whose seconds at some change point would not fit an unsigned 64-bit rational is rejected when built (`TEMPO_MAP_ERR_OVERFLOW`), never wrapped.
  - **Regions and default tempo.** A change point is a region and none is merged: a tempo repeating the previous one is still its own region, so the list says what the file said. Change points must be strictly ascending (two at one time leave no way to say which wins), and a tempo of 0 is an error. If no tempo is declared at 0, the MIDI default of 500,000 microseconds per quarter note (120 quarter notes per minute) covers the span before the first one as a defaulted region; `tempo_map_create_defaulted` is one defaulted region from 0. `tempo_map_is_defaulted` is true when every region is, so a consumer can tell a declared tempo from a default.
- `MetricalPosition` (`time/metrical_position.h`) is where a `MusicalTime` falls in a measure: `{measure, offset}`, the measure number as `MeterMap` numbers it (the first full measure is 1, a pickup is 0) and an offset into that measure, an exact `Duration` in whole notes from the measure's start. It is pure arithmetic and makes no beat claim: it holds no `TimeSignature`. The roadmap's "measure, beat, subdivision" is split across layers: the kernel value is measure + offset, and beat and subdivision are `theory/meter`'s reading of that offset (`standard_meter_beat_position`), with a `BeatStrength` from `standard_meter_beat_strength`. The kernel never includes standard-meter.
  - **Derivation.** `metrical_position_from_time(map, time, &position)` uses a `MeterMap`. All arithmetic is exact and checked: a value that does not fit, including a measure number past `int`, is `METRICAL_POSITION_ERR_OVERFLOW`, never a wrapped number. A time before 0 is an error. A `MeterMap` is open-ended, so there is no "past the end" error.
  - **Offset semantics.** The offset is never negative and is less than the length of the measure it is in. In a short measure (cut short by a mid-measure meter change) the offset runs from where that measure started and only up to its real, short length.
  - **Barlines.** A time exactly on a barline is the next measure at offset 0 (a barline belongs to the following measure, as in `MeterMap`): one whole note in 4/4 is measure 2, offset 0.
  - **Pickups.** A pickup is measure 0, and its offset is measured from where a full measure would have started, as in a score: a one-quarter pickup in 4/4 is at offset 3/4 (beat 4), and an eighth-note pickup in 6/8 at 5/8. The full measure is the one the file implies. A partial first measure ended by a later time signature uses its own signature. A short leading signature (a 1/8 region before 12/8) uses the following region's: the pickup eighth is at offset 11/8 of a 12/8 measure. `metrical_position_reading_signature(map, measure, &signature)` returns the signature a measure's positions are read in, which is the one to pass to standard-meter. No pickup is inferred from note content.
- **Exact arithmetic and overflow.** Law 19: time is exact `Rational`, never float or double. Arithmetic on time values is `core/rational.h`, and a time value is read as its `.value`. Overflow is always reported, never wrapped: `musical_time_plus` is `MUSICAL_TIME_ERR_OVERFLOW`, `duration_plus` is `DURATION_ERR_OVERFLOW`, the tempo map its existing overflow code.

## Dependencies

Depends on `identity` (L0) and `core` (L1) only.
