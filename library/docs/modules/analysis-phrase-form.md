# Analysis: phrases and form

PhraseBoundaryDetection, PeriodDetection, SentenceDetection, FormStructureDetection and ThematicReturnDetection in the kernel `analysis` module. [Docs index](../README.md)

## PhraseBoundaryDetection

`PhraseSegmentation` (`analysis/phrase_segmentation.h`) packages an already-determined `is_boundary` per point into an `Interpretation` targeting that point's event. It is the generic, caller-supplies-the-classification step, the role `CadenceDetection` has under `CadenceClassification`.

`PhraseBoundaryDetection` (`analysis/phrase_boundary_detection.h`) computes the signal on top of it. Given a `NoteEvent` sequence annotated per point with `CadenceDetection` or `CadenceClassification` output (`has_cadence` plus the winning candidate label as `cadence_type`, where `"unclassified"` is a legitimate value) and Contour or RhythmicPattern discontinuity observations (`has_discontinuity`, for example a rest or a clear directional or rhythmic break, supplied by the caller), it derives `is_boundary` values:

- Primary signal: any detected cadence at a point is a boundary, whatever its type.
- Secondary signal: a contour or rhythm discontinuity only counts as a boundary once `max_length_without_cadence` points (default `PHRASE_BOUNDARY_DETECTION_DEFAULT_MAX_LENGTH` = 8, a stated default, not Registry-settled) have elapsed since the last boundary with no cadence among them.

It packages the `is_boundary` values into a `PhraseSegmentationPoint` array and delegates to `phrase_segmentation_analyze` for the plain boundary `Interpretation`. `PhraseSegmentationClaim` has no room for which signal fired or which cadence type applied, so `PhraseBoundaryDetection` reports that as a separate `Interpretation` (`phrase_boundary_detection_signal_analyze`, `PhraseBoundaryDetectionSignalClaim`: signal kind and, when it applies, cadence type) targeting the same event. Two Interpretations on one target is the competing-or-complementary pattern `Chord` and `Key` use.

`phrase_boundary_detection_build_occurrences` groups the points between boundaries (boundary-inclusive) and constructs one `PhraseOccurrence` (L5, `structure/phrase_occurrence.h`) per phrase, spanning that phrase's event range. A `Phrase` (L4, `containers/phrase.h`) is constructed transiently per phrase to obtain the id the `Occurrence` targets, then destroyed. A trailing run of points with no closing boundary signal still becomes a final `PhraseOccurrence`, so all material ends up in some phrase.

Out of scope: pitch or interval math beyond what Contour and RhythmicPattern provide, and L9 query infrastructure (`PatternMatching`, `SimilarityModel`, `SearchResult`).

## PeriodDetection

Period and Sentence structures have no named type in the System Registry. `PeriodDetection` (`analysis/period_detection.h`) adds no new type: it emits a generic `Interpretation` whose claim describes the antecedent and consequent relationship.

Given an ordered sequence of `PhraseOccurrence`s, each annotated with the `CadenceType` that triggered its boundary, it identifies a period pair between two consecutive phrases when the first's cadence ranks strictly weaker than the second's. The kernel does not own that order: the caller injects a ranking function (`PeriodDetectionRankFn`, `int (*)(CadenceType)`, larger is stronger, `<= 0` is not rankable) in `PeriodDetectionInput.rank` and in `period_detection_build_relationships`. `frameworks/standard-harmony` owns the order (`harmony_cadence_strength`, weakest to strongest: half < deceptive < plagal < authentic (unspecified) < imperfect authentic < perfect authentic; a subverted cadence ranks 0 and `CADENCE_TYPE_UNKNOWN` is unranked), so a caller passes it in:

```c
PeriodDetectionInput input = {entries, entry_count, harmony_cadence_strength};
```

Analysis code never includes a framework header. A pair where either phrase's cadence is unranked (`CADENCE_TYPE_UNKNOWN`, subverted, or invalid) is skipped entirely, with no Interpretation and no guess.

An `Interpretation` has a single `EntityID` target, but a period pair is two `PhraseOccurrence`s, so the link is a `Relationship` (L6, `relationship/relationship.h`). `period_detection_build_relationships` builds one `Relationship` per identified pair: `source_id` is the antecedent `PhraseOccurrence` id, `predicate_name` is `"precedes"` (in `PredicateDefinition`'s vocabulary), `target_id` is the consequent id. `period_detection_analyze` emits one `Interpretation` per pair targeting that `Relationship`'s id, derived deterministically from the same phrase-id pair so the two calls agree without one constructing the other's output. It carries a `PeriodDetectionClaim` (both phrase ids and cadence types) and a 1/1 scalar-confidence `Uncertainty`. `analysis` already depends on all four L6 modules, so this adds no dependency.

## SentenceDetection

`SentenceDetection` (`analysis/sentence_detection.h`) adds no new named type either. A Sentence has three parts (statement, repetition, continuation), so it chains two `Relationship`s: `repetition --"transformed_from"--> statement` and `continuation --"transformed_from"--> repetition`. Each has its own `Interpretation` (target is that `Relationship`'s id), and both carry a shared `SentenceDetectionClaim` recording all three occurrence ids. `"transformed_from"` is in `Relationship`'s predicate vocabulary and points from derived to source, unlike `"precedes"`, which runs earlier to later.

`SentenceDetection` consumes the statement and repetition pair; it does not detect it. The caller, who has run motive matching, supplies each pair's two `MotifOccurrence` ids and the statement's own `MotifWindow` (`Contour`, `RhythmicPattern`, event ids). `SentenceDetection` adds the third part. Given a caller-sliced `continuation_candidate` window (the phrase's remaining material after the repetition, up to but not including its cadence; where that cadence falls is the caller's decision), it decides whether the candidate qualifies through `SentenceContinuationMatching` (`analysis/sentence_continuation_matching.h`).

The `Fragmentation` transform (`transform/fragmentation.h`) does not serve here: it only clones a supplied `extracted_event_ids` set out of a source `Structure`'s events and has no comparison logic. `SentenceContinuationMatching` extends `MotifWindowMatching`'s exact-window equality rule to a variable-length prefix match. A candidate qualifies when its event count is at least 2 (a minimum-length floor that avoids a single-note match) and strictly shorter than the statement's, and its Contour direction sequence and RhythmicPattern duration sequence each equal the statement's over that same prefix length. Contour (`semantics/contour.h`) carries direction only, never pitch, so a transposed continuation matches by the same rule.

When no candidate is supplied, or the candidate does not qualify, `SentenceDetection` produces no output for that pair. A phrase with no detected Sentence is a normal outcome (it may be a Period, or neither). `sentence_detection_build_relationships` mirrors `period_detection_build_relationships`: `AnalysisResult` holds only `Interpretation` and `Evidence`, so a caller who wants the `Relationship`s calls it in addition, and the ids match because both mint them from the same occurrence-id inputs.

## FormStructureDetection

`Section` (`containers/section.h`, L4) is a real, non-transient container: `id` plus `phrase_ids`. `FormStructureDetection` (`analysis/form_structure_detection.h`) mints a `Section` per identified group directly with `section_create`; nothing is transient.

Given the same ordered, cadence-annotated `PhraseOccurrence` sequence `PeriodDetection` consumes, it answers a coarser question: which cadences close a Section rather than a phrase. Only `CADENCE_TYPE_PERFECT_AUTHENTIC` and `CADENCE_TYPE_IMPERFECT_AUTHENTIC` count as structural, because they are the only two cadence types that achieve tonic resolution. This is a stated default, narrower than `PeriodDetection`'s ranking, and not Registry-settled. `CADENCE_TYPE_AUTHENTIC_UNSPECIFIED`, plagal, deceptive and half cadences work as internal phrase punctuation but never as section-ending closure, and an ambiguous PAC or IAC call is never promoted to structural. A structural cadence at entry `i` (other than the last entry) closes a Section spanning the entries since the previous boundary through `i`. A trailing run of entries after the last boundary that never reaches another structural cadence does not become a Section. With no structural cadence anywhere there is no boundary, no Section and no output.

Consecutive Sections are linked as `PeriodDetection` links phrases: one `Relationship` each (`source_id` is the earlier Section id, `predicate_name` is `"precedes"`, `target_id` is the later Section id), then one `Interpretation` targeting that `Relationship`'s id, carrying a `FormStructureDetectionClaim` (both Section ids and the earlier Section's closing cadence type). `form_structure_detection_build_sections` and `form_structure_detection_build_relationships` mirror `PeriodDetection`'s split (`AnalysisResult` never owns Section or Relationship objects), minting matching ids from the same boundary computation.

## ThematicReturnDetection

`ThemeOccurrence` and `Theme` (L5, `structure/theme.h`, `structure/theme_occurrence.h`) are shells the System Registry marks "No (example only)", the same non-normative status `Motif` carries. `ThematicReturnDetection` (`analysis/thematic_return_detection.h`) adds no new named type.

It applies `MotifWindowMatching`'s comparison rule at Theme granularity. The rule is granularity-agnostic: it compares whatever `Contour` and `RhythmicPattern` the caller built for a window. A `ThemeOccurrence`'s region (`region_event_ids`, possibly several phrases) is such a window, and the caller builds one `MotifWindow` per `ThemeOccurrence` as for any other `MotifWindow`. `ThematicReturnDetection` implements the comparison itself rather than calling `motif_window_matching_find`, because that function reports only a per-window "matched something" flag, and a return needs the matching pair (which later `ThemeOccurrence` recalls which earlier one). `MotifWindowMatching`'s public surface is untouched.

The predicate is `"resembles"`, not `"transformed_from"`: a return asserts similarity with no claimed direction of derivation. For every ordered pair of `ThemeOccurrence` entries (earlier, later) whose windows match, it builds one `Relationship` (`source_id` is the later `ThemeOccurrence` id, `predicate_name` is `"resembles"`, `target_id` is the earlier id; the claim is about the Theme material, not the Section it sits in) and one `Interpretation` targeting that `Relationship`'s id, carrying a `ThematicReturnDetectionClaim`. No matching windows means no output. `thematic_return_detection_build_relationships` follows the same `AnalysisResult`-never-owns-`Relationship` split as the other analyzers.

Minimum window length: any window below `THEMATIC_RETURN_DETECTION_MIN_WINDOW_LENGTH` (4 events) is excluded from matching, because short generic windows (for example a 3-event stepwise run) match across unrelated occurrences. It is a fixed constant, local to `ThematicReturnDetection`, like `SentenceDetection`'s minimum of 2 continuation events and `PhraseBoundaryDetection`'s default of 8. 4 is a stated default, not Registry-settled, and may move as more of the corpus is checked. `motif_window_matching_find` has no such floor; its callers hand it short, curated candidate windows.

Windowed and varied matching: a return is not a whole theme repeating another note for note. For each pair of `ThemeOccurrence` windows the detector slides a stretch of `window_length` events (default 6, or the shorter theme's length when that is less, never below 4) across both and compares every pair of stretches with `motif_window_matching_compare` (`MotifWindowMatching`'s rule, returning scores). The contour score is the share of equal up, down and same directions, the rhythm score the share of equal durations, each 0 to 1. The similarity of a stretch pair is the lower of the two, and the best stretch pair is the match. A pair is a return when its similarity reaches `threshold` (default 0.8). A later theme that restates only the opening idea of an earlier one is found wherever the idea sits, a transposed statement matches (contour direction is transposition-invariant), and one changed duration or direction in six still matches while a different rhythm or shape does not. Both settings live in `ThematicReturnDetectionConfig` (`thematic_return_detection_default_config`, the optional `config` field on `ThematicReturnDetectionInput`, `thematic_return_detection_build_relationships_configured`); a NULL config means the defaults. The default threshold is a stated default, not tuned: the Framework v1 returns are blocked upstream (no L3.6 theme exists where the annotated returns are, C8), so the harness shows no threshold separation (identical results from 0.5 to 1.0). The evidence is recorded twice: `ThematicReturnDetectionClaim.similarity` on the Interpretation, whose confidence is the similarity in thousandths, and a `thematic-return-similarity` `Value` in the `qualifiers` of the "resembles" `Relationship` (`ThematicReturnSimilarity`: contour score, rhythm score, similarity, the two stretch offsets and the stretch length).

## The soprano of the form input

The phrase, idea, theme and expansion analysis (`frameworks/standard-form/analysis/`) reads a soprano line, the cadences and the segments that `chain_build_form_input` (`chain/`) builds. The soprano is the outer line on the voice segments (`analysis_chain_voice_segments`, `analysis_chain_outer_voices`), one note per soprano note, consecutive voice segments on one note id being one note (R-377). It is not the outer lines sampled at each harmonic span's start, which keep one note per span and lose the rest of the melody. The harmonic segments and the cadences stay on the chord segments.

## The phrase grid

Phrase first (R-389, R-391): a piece is cut into units of 4, 8 or 16 measures before any cadence is trusted, and the cadences then confirm the units' ends. `standard_form_find_phrase_grid` (`frameworks/standard-form/analysis/analysis_phrase_grid.h`) finds the grid from the melody (one note per attack) and the candidate cadences (the found ones, both readings of a two-reading cadence, and the half readings). Nothing in the chain calls it yet.

Evidence of a measure m: the cadence arriving in m or held into it (1.0 for a perfect authentic, 0.8 for an imperfect authentic, an unspecified authentic or a half cadence), 0.3 when the last melody note starting in m lasts at least half the measure, 0.3 when no note sounds in m's last half beat, and 0.3 when the notes of m + 1 and m + 2 (at least 6) repeat the onsets and semitone steps of an earlier pair starting at least 5 measures before.

A unit [f, e] scores evidence(e) - 0.3, minus 0.6 when its length is not 4, 8 or 16, minus 0.1 when it is elided, plus the cadence evidence at its half measure when it is 8 or 16 long (an antecedent ends there). A unit is 2 to 16 measures long, a pickup counts in no length, and a unit starts on the previous unit's last measure (an elision) only when an authentic cadence arrives there. The grid is the tiling of the highest total, found by dynamic programming over (start measure, elided); of equal totals the one reached first wins. The constants are measured, never fitted to a piece.

`standard_form_segment_phrases_on_grid` (`analysis_phrase.h`) ends a phrase at a unit's last or half measure that holds a goal cadence (at the point's measure, not the arrival chord's end), and at a unit's last measure without one only when the phrase would pass 16 measures or no unit follows (the discontinuity signal, which on the grid is the 16-measure cap). `standard_form_identify_themes_on_grid` (`analysis_theme.h`) pairs two phrases into one theme only when the first ends on a unit's half measure and the second on that unit's last. One-phrase themes are unchanged.
