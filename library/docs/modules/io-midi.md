# io: MIDI import

The MIDI import of the `io` module: the complete import, with the key signatures, meter and tempo it reads. [Docs index](../README.md)

Key signatures: every Key Signature meta-event (`0xFF 0x59`) of an SMF buffer, with its position, in time order, as the `key_signatures` of a `MidiImport`.

- **Entry fields.** Each `MidiKeySignatureEvent` carries a `KeySignature` (`pitch/key_signature.h`), a `MidiModeHint`, the position as `MusicalTime`, the raw `tick` and `track_index`, and the raw `sharps_flats` (sf) and `mode_byte` (mi) bytes. The list is owned and released with `midi_key_signature_events_destroy`.
- **KeySignature versus mode hint.** `midi_key_signature_build(sf, &out)` builds the `KeySignature` for an sf value in -7..7 in circle-of-fifths order (sharps F C G D A E B, flats B E A D G C F; sf 0 is empty); out-of-range sf is an error. It is a spelling only and makes no claim about key or mode. The mi byte is a hint carried next to the `KeySignature`, never part of it: `mi` 0 is `MIDI_MODE_HINT_MAJOR`, 1 is `MINOR`, anything else is `UNKNOWN` (the event is kept). Turning sf and mi into a key is analysis work, not done here.
- **Position.** Ticks accumulate per track and convert as `MIDIImporter` does: `MusicalTime = tick / (4 * division)`, an exact whole-note fraction. SMPTE division is rejected as unsupported, and so is a division of 0.
- **Order and duplicates.** Events from all tracks are merged and ordered by tick, then track index, then byte order within a track. An exact duplicate (same tick, same sf, same mi) is reported once, on the lowest track. Different events at the same tick are all kept, in that order.
- **Malformed events and errors.** A malformed `0xFF 0x59` is skipped and scanning continues: a length other than 2, or an sf outside -7..7. Structural SMF errors (null buffer, truncated, bad header, unsupported format or division, bad track) are reported by the import itself. A file with no key signature events returns OK with zero entries.

`midi_importer_import_complete`: the public entry point that returns everything the importer reads from one parse. It fills a `MidiImport` (release with `midi_import_destroy`; NULL and a zeroed struct are safe) with the notes and their `PitchNumericValue`s, `note_tracks[i]` and `note_channels[i]` (the MTrk index and MIDI channel of note `i`), the `MidiMeterImport`, the `MidiTempoImport`, the `MidiKeySignatureEvents`, the header's `format` and `division`, and one `MidiTrackInfo` per track chunk.

- **One parse, one pass per track.** `smf_reader_parse` runs once and `midi_event_decoder_scan` walks each track once, collecting note events, program changes, the track name, time signatures and set-tempo events together. Key signatures come from the same walk: `midi_key_signature.c` exposes a collector (`midi_key_signature_collector_meta` per meta-event, `_finish` once) that the walk feeds.
- **Tracks.** `MidiTrackInfo` has the chunk `index`, the `name` (the first `0xFF 0x03` in the chunk, NULL when absent) and the `programs`: each `0xC0` program change in byte order with its channel, program number (0-127), tick and exact `MusicalTime` (`tick / (4 * division)`). A chunk with no events has a NULL name and no programs.
- **Internal.** `smf_reader.h` and `midi_event_decoder.h` stay implementation details of the module; the one variable-length-quantity reader is `midi_event_decoder_read_vlq`, used by the decoder and the key signature walk. On any failure `*out` is untouched. `io/tests/io/test_midi_import_complete.c` checks the complete import on a type 0 and a type 1 fixture and the five corpus files, and runs under valgrind. `io/tests/io/midi_import_split.h` hands a test the notes with the meter, tempo or key signatures it asks for.

The meter: the `meter` of a `MidiImport`.

- **MidiMeterImport.** `meter_map` is the file's time signatures as a `MeterMap` (`time/meter_map.h`; measure numbering, the pickup rule and barline ownership are documented there). A file with no `0xFF 0x58` gets a single 4/4 region marked defaulted, so a consumer can tell a declared meter from a default. `end_time` is the time of the last note-off in whole notes (0 with no notes); pass it to `meter_map_measure_count`. `conflict_ticks` lists ticks where different signatures shared a tick. Release with `midi_meter_import_destroy`. On any failure no output is written.
- **Time signature decoding.** The event decoder reads `0xFF 0x58` (length 4, `nn dd cc bb`; `dd` is a power of two, so `6 3` is 6/8) from every track into `TimeSignature`s with a tick position. `cc` and `bb` are not read beyond the length. Events merge in time order (tick, then track, then byte order): an exact duplicate is merged, and if different signatures share a tick the last in track order wins and the tick is reported in `conflict_ticks` (the library prints nothing). Malformed events are skipped, as the key signature scan skips its own: a length other than 4, `nn` outside 1..64, or `dd` above 4 (a bottom number past 16). SMPTE division is rejected as elsewhere.
- **Measures follow the file.** Measure numbers come from the file's own time signature events only; no meter or pickup is inferred from note content. A file whose meter disagrees with its score is imported as the file says. Two corpus files show this: `Bach 114.mid` declares 4/4 for a 3/4 minuet (24 measures where the score has 32), and `Mozart 545.mid` is the first movement only (cut at the start of measure 147 by `tests/fixtures/tools/cut_midi.py`; the uncut file held three movements on one timeline and numbered straight through to 338). `Field 1.mid`'s first note sits nine eighths into its first 12/8 measure, the shape of a padded upbeat, which the importer numbers as measure 1 because the file declares no pickup. `io/tests/io/test_midi_corpus_meter.c` records each case.

The tempo: the `tempo` of a `MidiImport`.

- **Symbolic time stays tempo-independent.** Note positions and durations are whole-note fractions of ticks and the header's division alone, as before. Reading the tempo does not change them. The `TempoMap` answers a separate question, how many seconds a `MusicalTime` is; it is not an input to the notes.
- **MidiTempoImport.** `tempo_map` is the file's set-tempo events as a `TempoMap` (`time/tempo_map.h`), one region per distinct tick. A tempo at tick 0 is the first region. With none at tick 0 the MIDI default of 500,000 microseconds per quarter note (120 quarter notes per minute) applies from 0 as a defaulted region; a file with no set-tempo event is one defaulted region, so a consumer can tell a declared tempo from a default. `conflict_ticks` lists ticks where different tempos shared a tick. Release with `midi_tempo_import_destroy`. On any failure no output is written; a file whose seconds would overflow a `TempoMap` fails with `MIDI_IMPORT_ERR_ALLOC`.
- **Set-tempo decoding.** The event decoder reads `0xFF 0x51` (length 3, one big-endian 24-bit value, microseconds per quarter note) with its tick from every track. Events merge in time order (tick, then track, then byte order): an exact duplicate is merged, and if different tempos share a tick the last in track order wins and the tick is reported in `conflict_ticks` (the library prints nothing). A tempo that repeats the previous one at a later tick is kept, so the region list is what the file says. Malformed events are skipped: a length other than 3, or a tempo of 0. SMPTE division is rejected as elsewhere.
- **File values, not score values.** The corpus tempos are whatever the files encode. `io/tests/io/test_midi_corpus_tempo.c` records each piece's first tempo and region count (Field 1 has 602 regions, Mozart 545 has 24) and says so; nothing here infers a tempo or rubato from note timing.
