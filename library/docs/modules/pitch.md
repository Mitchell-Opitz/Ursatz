# pitch

[Docs index](../README.md): the Ursatz docs by topic.

Layer L2 (`music-pitch`). Path `src/pitch/`, tests `tests/pitch/`. Depends on `identity` and `core` only. Sibling of `time`; the two do not depend on each other.

## Provides

`PitchIdentity` (an opaque token identifying a pitch), `PitchSpelling` (a written pitch name made of letter, accidental, and octave), `TuningSystem` (a tuning definition), `Clef` (a sign -- G, F, or C -- anchored on a staff line, naming the reference pitch G4, F3, or C4), and `StaffPosition` (a notehead's line/space step count from the bottom line of a five-line staff), `Accidental` (double flat, flat, natural, sharp, or double sharp, with semitone offsets -2 to +2), `KeySignature` (an ordered list of letter and accidental-offset entries), and `GenericInterval` (the size of an interval counted in letters, 1 or more). `pitch/clef_resolution.h` maps between the two: a `StaffPosition` plus a `Clef` resolves to a letter and octave, and back.

## Notes

- `PitchIdentity`'s equality is RESOLVED, not deferred: it is strict identity (value equality on the raw token bytes, read with `pitch_identity_token`) by design, permanently. This answers "is this the same token," a different question from theory-relative equivalence (octave equivalence, enharmonic equivalence under some tuning, etc.), which no kernel type holds. `PitchIdentity` itself will not gain a second equality notion.
- `PitchIdentity`'s token is intentionally opaque and is not an `EntityID`. Its constructor takes a raw byte buffer, not an `EntityID*`, so there is no path to construct one from an EntityID-typed value.
- `PitchIdentity` construction takes no tuning-system parameters. No 12-TET, no A440, no MIDI note number. None should be added before Deliverable D exists.
- `PitchSpelling`'s `accidental` field is treated opaquely (an integer offset); its exact model is also deferred to Deliverable D. Enharmonic equivalents (C# and Db, for example) are intentionally not value-equal, even though they may sound identical under some tunings.
- `TuningSystem` holds only identity and a name (e.g. "12-TET", "just intonation"); it does not encode any tuning's actual ratio set. It does not build on `core/entity.h`'s `Entity`, mirroring `theory/framework.h`'s `Framework`, for the same category-boundary reason.
- `Clef` supports any (sign, line) pair with line 1-5, with presets for treble, bass, alto, tenor, soprano, mezzo-soprano, and baritone. It also carries a sounding octave shift (-1, 0, +1) for octave treble clefs; a double treble clef is the same as the octave-down treble, since its glyph difference is presentation only. A neutral clef (`CLEF_SIGN_NEUTRAL`, built only with `clef_create_neutral`) marks an unpitched staff: it has no line, reference pitch, or shift, and clef resolution refuses it with `CLEF_RESOLUTION_ERR_UNPITCHED`. `clef_sounding_pitch_at_position` applies the shift to the written pitch. Instrument-level conventions (e.g. piccolo always sounding an octave higher) are not modeled. `Clef` is deliberately not attached to a staff: a clef can change mid-staff, so placing one is a later concern.
- `StaffPosition` stores only the step count; ledger-line count and line/space are derived. Clef resolution deals in letter and octave only -- accidentals are not part of staff placement. The rules that use these types (ledger lines, stem direction, seconds) are not modeled in a framework; this module holds only the types.
- `Accidental` maps to and from the integer offset `PitchSpelling` already stores in its accidental field; `PitchSpelling` itself is unchanged, so its accidental model stays opaque and deferred to Deliverable D. A natural has offset 0 but is a distinct kind from no accidental. "Semitone" is only the unit of the offset: how many semitones make an octave is a tuning matter and is not defined in this module. Glyph variants (double sharp as a cross or as two sharps) are presentation and not modeled. Enharmonic equivalents stay value-unequal on `PitchSpelling`; the equivalence is a rule that no framework models.
- `KeySignature` is a value holding entries in written order (letter plus a -2..+2 offset, the same integer `PitchSpelling` stores); the empty signature is valid and is the one with no sharps or flats. It carries no theory: mixed, repeated, or out-of-order entries are representable. The conventional order (F C G D A E B, flats reversed), the limit of seven, and which key a signature belongs to are rules of `frameworks/standard-tonality/`. It has no `EntityID` and no mutator.
- `GenericInterval` is the written size between two spellings: the count of lines and spaces from the lower note up to the upper, both ends included (a note to itself is 1, C to G is 5), by letter and octave only, so accidentals never change it. Sizes of 8 or less are simple, larger are compound, and an octave adds 7. The upper note may not be below the lower. It carries no quality (perfect, major, minor, augmented, diminished): that is a rule of `frameworks/standard-tonality/`. It is not `semantics/interval.h`'s `Interval`, which holds semitone distances between opaque `PitchIdentity` tokens and does not represent diatonic distance. Value type, no mutator.
- `pitch/pitch_arithmetic.h` is the public spelling arithmetic, theory-neutral (no key, mode, or scale): `pitch_letter_semitone` (C=0 ... B=11), `pitch_letter_index` (C=0 ... B=6), `pitch_letter_offset` (wraps both ways), `pitch_class_of_letter` (0 to 11), `pitch_spelling_fifths` and `pitch_spelling_from_fifths` (line of fifths, C=0, G=1, F=-1, F#=6, Bb=-2; each sharp adds 7), `pitch_spelling_name` and `pitch_spelling_parse_name` (`C`, `F#`, `Bb`, `Cx`, `Ebb`; parse takes `#`, `b`, `x`, `bb`, `##` and an optional octave, and rejects trailing text), and `pitch_class_name`. It assumes twelve semitones to the octave (the MIDI layout), the one tuning assumption in this module; enharmonic spellings stay distinct. Frameworks use these instead of private letter tables.
- `pitch/midi_pitch.h` is the one reading of a MIDI number: `pitch_class_of_midi` (0 to 11 for any int), `pitch_spelling_of_midi` (octave 4 C is 60; sharps for `key_fifths >= 0`, flats below; the caller destroys the spelling), `key_signature_from_fifths` (-7 to 7; sharps in the order F C G D A E B, flats in the reverse) and `key_tonic_name` (C, Db, D, Eb, E, F, F#, G, Ab, A, Bb, B by tonic pitch class). Callers use these instead of their own mod-12, spelling or fifths code.
- Degree and key signature functions are `frameworks/standard-tonality/tonal_key.h` (see that README). The major-scale tables in `common-practice-minimal`, `standard-harmony` and `galant-schemas` stay: those frameworks do not depend on standard-tonality, and frameworks may not depend on each other.

## Dependencies

Depends on `identity` (L0) and `core` (L1) only.
