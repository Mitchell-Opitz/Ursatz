# Changelog

The Composer versions and what each changed. Back to the [docs index](README.md). Older entries are in the [changelog archive](changelog-archive.md).

## Unreleased (phase L2)

Triplets run through the motive texts and themes (R-435, R-442, B3). The Ursatz and Analyzer pins move to the merges of the triplet motive times (`49a5523`, `4374060`). A duration token is a letter then up to two dots or a `3`, a triplet value two thirds of the plain one (`q3` 1/6, `e3` 1/12, `s3` 1/24; `q.3` is refused): `motive_notes.c` reads it and `motive_text.c`, `motive_analysis.c` and `api_develop.c` write it for a time whose denominator is divisible by 3, so every other text is unchanged. `grow_check.c` counts fragments in 384 ticks per whole note, and a theme that scales the rhythm of a motive with triplets passes over a ratio whose result has none (`grow_theme.c`). `test_form_plans` masks the pinned Ursatz commit before it hashes a plan, so a pin bump no longer moves the pinned form plans (their fixtures were recorded once more). New: `test_grow_triplets` (slow, with `test_grow_triplets_smoke`), a `listen` case for a triplet motif. Binary motives and every snapshot are as before. See [motive-format.md](motive-format.md#triplet-values-in-the-texts) and [theme-request.md](theme-request.md).

## Unreleased (phase P45)

The API serves the forms (R-428, R-430, R-433, B1): `composer_api_forms` gives the seven built-in forms in registry order, each with its label, versions, settings, regions and, for every size, its sections (role, length, beginning and ending, cadence, keys, motive, return, layers and the slots of its theme with their ideas), and, for the game loop, its roles, loop roles, cadences and default ending. The vocabulary's `theme_slots` entries gain `required` (the basic slot) and its `piece_intos` entries gain `beginning` and `ending` where the archetype is one pairing, and the API is 1.13. `form_role_label` labels the roles, `api_piece_version_names` names the versions of a piece, and the API's allocation failure and JSON add helpers are shared (`api_fail_alloc`, `api_add`). A piece still composes only as the game loop and no output, snapshot or baseline moved. The changelog from P37 back is in [changelog-archive.md](changelog-archive.md) and the compose rates are in [grow-hearing.md](grow-hearing.md#compose-rates), so the docs are under their size limit again. See [api/vocabulary-and-validation.md](api/vocabulary-and-validation.md).

The piece entries compose any form (R-429, B2): `composer_api_piece` and `composer_api_piece_variations` read a piece request of `schema_version` 2 with `form`, `bars`, `count` and `modulate` (version 1 stays the game loop and refuses a `form`), compose a form with sizes as the one version `piece` (the plan is built again with each attempt's seed, so a modulating piece plans its keys again), write one of its sections again by its name, and vary it. The result names its versions by the form (`versions`, `plans`, a variation's entry), lists the sections of the size with their role, return and motive, and `musicxml_versions` gives the MusicXML of the later versions. `PieceMade` holds its versions by index, `describe_sizes` is `api_form_sizes_text`, `composer_api_validate` fills the size of a request with sizes, the `piece` command writes the first version and refuses an ending option for a form with none, the piece schemas describe both shapes, and the API is 1.14. A game loop request, version 1 or 2, answers byte-identically and no snapshot, plan, baseline or rate moved. See [piece-request.md](piece-request.md#a-piece-of-another-form-schema-version-2).

## Unreleased (phase L1)

The segments motive generator gets nine listening settings (R-420 to R-422, B1): `MotiveRandomPreferences` gains `accented_one_in`, `accented_types` (appoggiatura, passing, suspension on the beat, resolving to the next note), `avoid_repeats`, `leaps_per_motif`, `leap_recovery`, `pickup_from_accent`, `contrast_fidelity_min`, `long_on_weak` and `final_long`, all off by default, so with none set every motive, file and snapshot is byte-identical. `motive_random_forms` knows the suspension. They are set from C only; the preferences document, the vocabulary, the schemas and the API version come in B2. See [cli-random-motive.md](cli-random-motive.md).

The nine listening settings are in the preferences document (R-422, B2): the `motif` group reads, writes and checks them (`accented_one_in` 0 to 64, `accented_types` a weighted list, `leaps_per_motif` 0 to 11, `long_on_weak` 0 to 20, `contrast_fidelity_min` a ratio, the rest true or false), the vocabulary shows `accented_one_in_max` and `leaps_per_motif_max`, the random motive and theme request and response schemas and the vocabulary schema list the members, and the API is 1.12. A request without them, or with them at their defaults, composes what it always did. A `listen` settings file sets them. See [preferences.md](preferences.md).

## Unreleased (phase P44)

Stuck form runs are fixed at their two causes (R-418, B6). A minor half-cadence continuation or free phrase gets chords that fill it: `grow_chords_before_last` (`grow_theme.c`) counts the chords before the last, `draw_continuation` takes its cap and its split from it, and a free phrase's cap is at least what it needs. The key check hears the part of a section after a key change inside it from the change, in its new key (`piece_keys.c`), so a modulation inside a section is no longer downgraded to a tonicization. Every template completes 20 of 20 runs in `test_piece_keys` and the five `WILL_FAIL` are removed; the form baselines rise to binary 30, 60, 20, rounded binary 40, 120, 58, ternary 30, 90, 35, variations 60, 220, 184, loop 40, 60, 32 and layered 60, 180, 74. A game loop in D minor 4/4 with a free phrase ending HC composes. Runs that completed before give the same output and no snapshot moved. New: `test_grow_half_cadence`, `test_piece_structure minor_half_free`. Known limits are in [piece.md](piece.md).

The game loop is a form (R-419, B5): `forms/game-loop.json` is the last built-in form, with `"sections": "request"`, the roles `intro`, `body`, `turnaround` and `ending`, the loop of the body and the turnaround, the cadences a section with none gets and the default ending (the reader has these members now, `form_spec.h`, `schema/form.v1.schema.json`). `form_build_plan` builds it from `PieceRequest.sections` (`form_build_request.c`), `piece_build_ending` builds the ending version, and `piece_request_check`, `piece_default_cadences` and `piece_default_ending` replace the structure's checks and defaults. `PieceSection`, `PiecePart` and `PieceFillKind` moved to `piece.h`, and the helpers a regenerated piece needs to `piece_reopen.h`. `PieceStructure`, `piece_structure_build_plan`, `piece_ending_plan` and `piece_structure.h` are removed, and `docs/piece-structure.md` is rewritten for the form, with the document's members in [forms.md](forms.md#the-game-loop). The API builds every piece through `piece_build_plan` and `piece_build_ending`: requests, responses and errors are as they were. Every plan stays byte-identical: `test_form_plans_pieces` pins the loop plan of the four piece request fixtures, and no snapshot, baseline or fixture changed. See [forms.md](forms.md).

The forms are data (R-416, B4): the six form templates are JSON documents in `forms/` (binary, rounded binary, ternary, variations, loop, layered), embedded at build time by `cmake/EmbedForms.cmake` and read by `form_spec_parse` (`form_spec.h`, `schema/form.v1.schema.json`). One builder, `form_build_plan` (`form_build.c`, renamed from `piece_request.c`), makes the plan of every form; `piece_build_plan` finds the built-in form named by `PieceRequest.form`, which is now a `const char *`. The sections, sizes, cadences, returns, motives and layers, the keys a piece may move to (`regions` and each section's `keys`) and which sections close in the home key come from the document: `piece_plan_keys` and `piece_plan_cadences` take the form and the size, `piece_check_cadences` takes a form (NULL: the built-in the plan is named for) and `ComposeConfig.form` names the form whose `checks` `compose_run` makes. `form_template.h`, `form_template.c` and the `FormTemplateKind` enum are removed. A form added as a document alone composes (`tests/fixtures/forms/bar-form.json`). Every plan and every composed output is byte-identical: `test_form_plans_templates` pins the plan of every form at every size, and no snapshot, baseline or fixture changed. The API, the plan format and the vocabulary do not change. See [forms.md](forms.md).

What a theme of each beginning and ending is made of is one table (R-416, B3): `theme_shape.h` and `src/grow/theme_shape.c` hold the beginnings and endings with their plan and standard-form names, the thirteen idea rows (idea, slot, first, role, place, length) and the four slots. `grow_request.c`, `grow_fidelity.c`, `grow_form.c`, the API vocabulary and the theme pairing reader of the plan JSON read it, and `grow_phrase_beginning` and `grow_phrase_ending` map by name through standard-form's `phrase_beginning_from_name` and `phrase_ending_from_name`. `GrowSlot`, `GrowIdea` and `GrowIdeaRole` moved from `grow.h` to `theme_shape.h`, which `grow.h` includes. `API_THEME_SLOTS` and `API_THEME_IDEA_SLOTS` are gone; the vocabulary JSON is byte-identical. The submodules are pinned at the cadence and form vocabulary (R-415). The API version, every seeded output, snapshot and baseline are unchanged. See [grow.md](grow.md).

## Unreleased (phase P43)

The `listen` command (R-403, R-404, B4): a batch of motifs or themes from fixed seeds, `--seed` + the sample's index, and a settings file, written as `<i>.mid`, `<i>.musicxml` and `<i>.json` in `--out-dir` with one line per sample in `listen.jsonl`. Themes come from a generated motif, a `--motif` file or a `--theme-request`; a sample that cannot be composed is a manifest line with its reason and the command goes on. `--print-settings` prints the default preferences document. The command is a client of the API: `composer_api_random_motive`, `composer_api_motive`, `composer_api_motive_render` and `composer_api_theme`, and the API version does not change. See [cli-listen.md](cli-listen.md).

The API carries the preferences (R-411, B3): the random motive and theme requests take an optional `preferences` member, the settings document of [preferences.md](preferences.md), and echo it in full in their response when it was given. The motif group steers the random motive's segments strategy; the melody and development groups reach a theme's grow (`GrowSetup.melody` and `.fidelity`); a theme request's motif group is accepted and has no effect. A bad member is refused with its path under `/preferences`, by the entry and by `composer_api_validate`. The vocabulary serves the default document as `preferences` and its limits as `limits.preferences`, the schemas gain the `preferences` object, and the API is 1.11. A request without the member gives what it gave before, and no snapshot changed. `GrowConfig.max_iterations` and `ComposeConfig.max_iterations`, which nothing set, are removed (A20261109-19); `FillConfig` keeps its own.

The motive generator and the fidelity check read their settings (R-411, B2): the segments strategy reads a `MotiveRandomPreferences` through `MotiveRandomOptions.preferences` (bars, pickup, shapes, chord plans, features, leap, rung moves, decorations and note lengths; the drawn strategy keeps its constants), and the melody stage's fidelity minimums are a `GrowFidelityTable` set through `GrowConfig.fidelity` and `ComposeConfig.fidelity` (`GrowSetup.fidelity` for the Development list). `ComposerPreferences` gains the `motif` and `development` groups. Every default is the constant it replaces and every draw keeps its random-number calls, so seeded output and the snapshots are unchanged; nothing calls the document from the API yet, and the API version does not change. See [preferences.md](preferences.md).

The melody stage reads its settings from `MelodyFillParams` (R-411, B1): the climax rise and slack, the share of draws that take the second-nearest chord tone, the attempts and the melodies kept (`MELODY_KEEP_MAX` 16), and a weight for each group of the checker's soft rules (`MelodyWeights`). A new `ComposerPreferences` (`preferences.h`) holds the melody group and reads it from and writes it to JSON with a path for every refusal. The defaults are the constants they replace, so with no preferences every output is byte-identical to before; nothing calls the document from the API yet, and the API version does not change. See [preferences.md](preferences.md).
